# Status Language

## Purpose

Status labels prevent governance documentation from implying trading capability, financial advice, performance, release, or client outcomes that do not exist.

## Status Labels

| Status | Meaning |
| --- | --- |
| Planned | Intended or designed, not yet created or published. |
| Scaffolded | Structure exists, but content may be incomplete or review-required. |
| Scaffolded / published | Public repository exists with initial standards, templates, examples, disclaimer, and validation. |
| Synthetic | Example uses fictional, placeholder, or fabricated-safe content. |
| Draft / review-required | Work is not approved for publication or external claim use. |
| Review-approved | Human reviewer approved the named governance artifact for the named use. |
| Published | Public artifact exists and is linked. |
| Paused | Work is intentionally stopped pending review or priority. |
| Deprecated | Artifact remains visible with archival or replacement context. |
| Private / Not public | Material is intentionally excluded from public surfaces. |

## Claim Rules

- Use `Synthetic` for examples.
- Use `Draft / review-required` for claim-review, monetization, portfolio, or offer material not yet approved.
- Use `Published` only when a public artifact exists.
- Do not use validation success as proof of trading performance, financial advice quality, client outcome, live bot operation, or production readiness.
